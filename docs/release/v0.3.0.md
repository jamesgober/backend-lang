# backend-lang v0.3.0 — From ir-lang to Running x86-64 Code

**Instruction selection, SSA register allocation with exact stack maps, and
whole-module emission, checked against ir-lang's reference interpreter.**
v0.3.0 turns the foundation into a backend: an ir-lang 2.0 module goes in,
and x86-64 machine code comes out with every function's offset, frame, and
call-site records (return address, stack map, landing pad), the relocations
a linker needs, and the module's data. It covers the integer, control-flow,
memory, call, and checked-arithmetic subset of ir-lang; floating point waits
on isa-lang's SSE forms, and everything not selected is refused with an
error that names what it waits on, never miscompiled.

## What is backend-lang?

The `-lang` family's own native code generator, replacing rented backends
(Cranelift, LLVM) on the path from a language sketch to machine code. It
sits between the optimizer (over ir-lang) and the encoder (isa-lang) and
owns instruction selection, register allocation, frames, and calling
conventions. jit-lang 2.0 and aot-lang 2.0 are its consumers.

## What's new in 0.3.0

### The Tier-1 path: `compile`

```rust
use backend_lang::Options;
use ir_lang::{Linkage, Module, Overflow, Signature, Type};

let mut m = Module::new("demo");
let sig = Signature::new(&[Type::I64, Type::I64], &[Type::I64]);
let f = m.declare_function("add", &sig, Linkage::Export)?;
let mut b = m.build(f)?;
let (x, y) = (b.param(0)?, b.param(1)?);
let s = b.add(x, y, Overflow::Wrap)?;
b.ret(&[s])?;

let c = backend_lang::compile(&m, &Options::sysv().with_frame_pointer(false))?;
// add rdi, rsi; mov rax, rdi; ret
assert_eq!(c.code(), [0x48, 0x01, 0xF7, 0x48, 0x89, 0xF8, 0xC3]);
# Ok::<(), Box<dyn std::error::Error>>(())
```

`compile` validates the module, then selects, allocates, and emits every
defined function into one buffer. Calls between the module's functions are
resolved; imports, globals, and the runtime entry points (trap handler, GC
poll, unwinder) stay relocations of the three kinds an ELF relocatable
carries (`PLT32`, `PC32`, `64`), which object-lang 0.2 writes as they are.
`Options` picks the platform convention (`sysv()`, `win64()`, `host()`),
the frame pointer, the runtime symbol names, and when a switch becomes a
jump table.

### Instruction selection

Every OPS integer operation (`add sub mul div rem floor_div floor_mod and or
xor shl shr min max neg abs not`) on every integer type, under every policy
ir-lang 2.0.0-alpha.1 carries:

- **`wrap`** computes modulo the width;
- **`trap`** branches to a per-function trap block that calls the runtime's
  trap handler with the OPS code;
- **`error`**, inside a `check` terminator, branches to the error edge with
  the OPS code as `err`.

Values narrower than 64 bits keep unspecified upper bits, as x86-64's
32-bit instructions leave them, and are extended by their signedness exactly
where the upper bits matter. Overflow comes from the flags at 32 and 64
bits, from an exact 32-bit result and a range check at 8 and 16, and from
the high half for unsigned multiplication. Division tests zero and
`MIN / -1` before `idiv` runs, so no policy is ever overridden by a processor
fault. Comparisons fuse into the branch or `select` that uses them;
conversions, loads and stores at every width, stack slots (over-aligned ones
included), field and element addressing, globals, function addresses, block
memory operations, and the x86-64 atomic subset are selected; switches
become bounds-checked jump tables when dense and balanced compare trees when
not.

### Calls, tail calls, safepoints, and landing pads

Calls direct and indirect, with stack arguments and multiple results, under
SysV and Win64 (the signature's tag decides; `c` and `fast` use the
platform's). Tail calls reuse the caller's incoming argument area. At every
safepoint the references in its GC list are stored into root slots before
the call and reloaded as the relocated values after it, exactly IR.md §9's
statepoint model: the slots are the call's stack map, no reference is in a
register while a collector runs, and no derived pointer can be. `invoke`
records its landing pad on the call site, and the pad's stub takes the
payload from `rax` and the relocated references from their slots; `resume`
calls the runtime. Unwind tables are not produced yet (see below).

### SSA register allocation

Liveness by SSA path exploration with a budget; one backward walk for last
uses, fixed-register liveness, and the registers each value must avoid
(call clobbers, implicit definitions); coloring in dominance order with no
interference graph; coalescing over copies, ties, and block parameters with
fixed-register hints; spill-everywhere with constants and addresses
rematerialized at their uses and other values read straight from their slot
when the instruction takes a memory operand; edge copies resolved by the
parallel-move resolver; callee-saved registers saved exactly when written.
`Function::verify_ssa` checks the precondition in linear time, with
dominators by Lengauer–Tarjan.

## Tests and verification

- **Differential testing.** A generator of valid, UB-free ir-lang programs
  (every integer op and policy, `check` error edges, loops whose back edges
  permute their parameters, dense and sparse switches, slots and globals
  through field and element addresses, block memory operations, direct,
  indirect, and tail calls, high register pressure) feeds sweeps that
  compile each program and compare its results or trap code with ir-lang's
  reference interpreter: in the x86-64 test interpreter under SysV, Win64,
  and both explicit convention tags on every platform, and natively
  in-process on x86-64 Linux and Windows. Arguments arrive with junk above
  their width; callee-saved registers and the stack pointer are checked
  after every return. A deep run at 3,000 programs per sweep (24,000 in the
  test interpreter, 9,000 natively) found nothing.
- **OPS conformance.** Every op × integer type × policy on the OPS edge
  values, against the interpreter, in the test interpreter and natively.
- **The allocator.** On every function selected from random programs, and on
  hand-built ones with cycles, ties, fixed registers, and pressure beyond the
  register file, an independent liveness checks the assignment point by
  point: no two live values share a register, no value is live across a
  write to its register, block parameters avoid each other and every
  live-in value. Hostile MIR never panics it.
- **Stack maps.** A moving collector in the tests walks the machine stack by
  the call-site records and frame layouts, moves every object a stack map
  names, rewrites the slots, and poisons the old copies; programs keep
  references across safepoints, calls that collect, and loops. Every stack
  map is checked to be exactly its GC list.
- **Landing pads.** A minimal unwinder over the same records runs `invoke`,
  cleanup, and `resume` against the interpreter's outcome.
- **Linking.** A module with function-pointer tables in data, indirect calls,
  a switch, and a checked add is written as an ELF relocatable by
  object-lang (its relocations read back and compared) and linked into a
  static executable that runs on Linux (ETXTBSY retried).
- **Dominators.** Lengauer–Tarjan against the textbook data-flow fixpoint on
  random graphs, and a 20,000-block chain with a shared sink.

## Fixed during the release

- A rematerialized `mov32ri` constant substituted into a 64-bit use kept its
  sign instead of its zero extension (`-1` became all ones, not
  `0xFFFF_FFFF`). Hand-written MIR only: selection loads constants with
  `mov64ri`. Covered by a new test.
- A value a terminator defines (a jump table's temporary) could in principle
  be chosen for spilling, which would have put a store after the jump. Such
  values are now never spill candidates.

## Dependency wiring

`ir-lang` `=2.0.0-alpha.1` is wired (pinned exactly while it is a
pre-release) and re-exported as `backend_lang::ir_lang`; its `interp`
feature is a dev-dependency, the oracle. `isa-lang` 0.2 stays wired.
`object-lang` 0.2 stays a dev-dependency.

## Breaking changes

`InstKind` gained `TailCall` and `Switch`, and `MirError` and `EmitError`
gained variants; all three are `#[non_exhaustive]`, so matches with a
wildcard arm are unaffected. `Emitter::finish` now accepts calls to names
declared with `declare_external` (they become relocations) instead of
reporting them undefined. Nothing was removed or renamed.

## Known limitations

Recorded with reasons in `dev/ROADMAP.md`:

- **Floating point and SIMD** wait on isa-lang's SSE forms (ISSUES P11);
  **`lock`-prefixed atomics** (`atomic_rmw` beyond `xchg`, `cmpxchg`) on
  isa-lang's `lock` prefix.
- **`shift = saturate`** (OPS v2) cannot be expressed in ir-lang
  2.0.0-alpha.1, so it is not selected.
- **No unwind tables** (Win64 `.pdata`/`.xdata`, DWARF CFI, LSDA): landing
  pads work only under an unwinder that follows the call-site records.
- **No PIC/GOT**: code linked into a shared object cannot reach another
  object's symbols.
- **Compile throughput** is below the 1M IR instructions/s target on the
  measurement machine (numbers below). The allocator reruns liveness and
  coloring on every spill round.

## Verification

Run on Windows x86_64 on Rust stable (1.95), 1.99, and the 1.85 MSRV:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo +1.99 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Counts at this release, identical with all and with no default
features and on 1.85: 19 unit tests (one a property test of dominators
against the data-flow fixpoint); 77 integration tests across 12 files, plus
5 ignored (statistics, timing, and a one-seed debugging aid); 333 doctests,
including every `rust` example in `README.md` and `docs/API.md`. The
default differential sweeps run 300 programs each (`BACKEND_DIFF_CASES`
raises it); a deep run at 3,000 per sweep (24,000 programs in the test
interpreter, 9,000 natively, each native one under SysV and Win64) plus OPS
conformance passed on the final code. On Windows the native sweeps run
in-process; the Linux process runs (`executable.rs`, `link.rs`) are part of
the Linux gate.

Benchmarks (`cargo bench --bench bench`, release profile, Windows x86_64,
library-only). **Measured while other builds shared the machine**: the
unchanged `mir_100k/build` ran about 2.9× slower than at 0.2, so these are
upper bounds.

| Benchmark | Time |
|---|---:|
| `compile` a 100,000-instruction ir-lang function (validate, select, allocate, emit) | ~175 ms (~0.57 M IR instructions/s) |
| Its selection alone / emission alone | ~36 ms / ~39 ms |
| `compile` a 20,000-statement function under heavy register pressure | ~512 ms |
| Native `fib(25)` vs ir-lang's interpreter | 0.38 ms vs 73 ms |
| Native 1,000,000-iteration loop vs the interpreter | 0.53 ms vs 154 ms |
| Native 1 KiB memory kernel ×20 vs the interpreter | 28 µs vs 4.2 ms |

With less load, the ignored timing test measured the whole pipeline at
0.88–0.99 M IR instructions/s on the same function. **The ≥1 M/s target is
not demonstrated.** Register allocation is the largest share: it reruns
liveness and coloring once per spill round (two or three rounds here).
